## 4. Verificação feita

Um script Python reproduziu as regras do build:
- **Programas:** títulos iguais em `modules` e `moduleContents`, `lessonsCount` igual ao número de passos, numeração dos passos, ícones válidos, quiz com uma única correta e módulo existente, sem `rating` nem `students`.
- **Mídia:** toda referência `/media/` existe e segue o padrão.
- **Catálogo:** todo id citado no `cobertura.json` existe.
- **Eventos:** ids e slugs únicos.
- **Anonimização:** nenhum nome proibido nos textos novos.

**Resultado: sem erros.** Também foram conferidos:
- os trechos de código do 404, com `node --check` e um teste do AES-GCM de ponta a ponta;
- as URLs das fontes, por WebFetch ou WebSearch; as que não puderam ser conferidas ficaram de fora.

**Falta o build oficial (Zod) e os testes do projeto: rode `npm run verificar`.**

## 5. Pontos de atenção

1. **Home do learn-tech.** A seção "Top Artigos" exibe todos os itens do blog: agora são 18 cartões na home. Recomendo limitar a home a 6 (uma linha de código em `learn-tech/src/pages/home/blog/Blog.jsx`); não alterei o código do site.
2. **Dados locais.** Sem `VITE_API_URL`, os sites usam os dados locais, que não têm este lote. Para ver: `08-piloto-codexperience.md`, seção 4.
3. **Programas 404, 503 e 602 com a API ligada.** Ficam clicáveis e completos. Com a API desligada, os dados locais continuam marcando-os como "Em breve" (divergência D1 de `02-contratos.md`).
4. **Fontes finas.** Os artigos de finanças e formação têm uma fonte externa cada, porque as páginas de editoras e escolas não puderam ser conferidas.
5. **Leitura humana.** Os textos foram escritos por Claude a partir do acervo: vale a sua leitura antes de publicar, principalmente os artigos que citam a sua experiência (rotina, networking, proposta de freelancer).
