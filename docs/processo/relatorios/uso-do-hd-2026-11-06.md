# Uso do hd: do arquivo à tela (06/11/2026)

Raio-x de todos os arquivos que estão hoje em `mundo-learn-tech/hd/`, camada por camada: inventário → acervo → API → sites. O objetivo é saber o que já virou conteúdo exibido, o que foi usado só como fonte, o que está bloqueado por regra e o que ainda não teve uso.

## Como foi medido
- **Arquivos:** leitura de todos os arquivos do hd, com o SHA-256 do inventário (`npm run hd:inventariar`).
- **Acervo:** cada hash ligado ao seu item em `content/acervo.json`, com estado e destinos.
- **API e sites:** cada destino conferido em três lugares: no `content/` do repositório, na API publicada (`/v1/...`) e nas cópias de reserva dos quatro sites.
- **Imagens:** cada imagem do hd comparada por hash perceptual (dHash 8×8) com as 378 imagens publicadas nos cinco repositórios.
  - Distância até 5: "exibida". Distância de 6 a 10: "provável", ou seja, a mesma foto tratada ou recortada.
  - Ícones e capturas do próprio site foram descartados como falso positivo.
- **Limite:** para texto (pdf, docx, txt, xlsx, html) não dá para provar, arquivo por arquivo, que o conteúdo foi usado. A medição só confirma que o item a que o arquivo pertence foi publicado.

## Por que hoje não dá para afirmar "100% usado"
1. **A decisão é por pasta, não por arquivo.** Um item `publicado` com 888 arquivos esconde 468 imagens que nunca foram para a tela.
2. **Não existe registro de uso por arquivo.** Não se sabe qual pdf virou qual parágrafo, nem qual foto foi descartada por ser parecida.
3. **Mídia sem destino:** os vídeos e as fotos excedentes de evento não têm regra, ficam "pendentes" para sempre.
4. **A verificação para na API.** Ninguém confere a página no navegador item a item. Esse é o papel do verificador, na fase 3.

## Proposta: definição de 100% e o processo
**100% usado = nenhum arquivo do hd sem decisão.** Todo arquivo termina numa destas situações, gravadas por arquivo no acervo:

| Uso | Quem marca | Conta como |
|---|---|---|
| `exibido` (com destino) | produtor; o verificador confirma | usado |
| `fonte` (com destino) | produtor | usado |
| `similar` (aponta o hash da versão publicada) | produtor | usado |
| `duplicata` | inventário, automático | resolvido |
| `tecnico` | inventário, automático | resolvido |
| `bloqueado` (com a regra: ex-empregador, dado pessoal, credencial) | triador; o autor confirma no A1 | resolvido |
| `descartado` (com motivo: sem qualidade, vazio) | autor no A1 | resolvido |
| `pendente` | padrão | **aberto** |

Como isso entra no fluxo de agentes (`agentes.md`):
1. **Inventário (fase 1):** marca sozinho `duplicata` e `tecnico`.
2. **Triador (fase 1):** propõe um uso para cada arquivo (não só para o item) e mostra no A1 a contagem por uso.
3. **Produtor (fase 2):** ao gravar o conteúdo, marca `exibido`, `fonte` ou `similar` em cada arquivo que usou.
4. **Verificador (fase 3):** confirma na tela os `exibido` e roda o relatório de uso do hd. A leva só fecha com **0 pendentes** (`npm run leva:status`).
5. **Relatório permanente:** este levantamento vira o comando `npm run hd:uso`, rodado a cada remessa.

Para os arquivos de hoje:

- **Os 271 de fonte:** o produtor confirma, item por item, quais arquivos foram de fato a fonte.
